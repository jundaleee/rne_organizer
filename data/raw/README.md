# 원자료(raw) 보관 규칙

이 폴더의 CSV는 **실험실에서 직접 측정한 원본 수치만** 들어간다. 전처리하거나
계산된 값(DDI 등)을 섞지 않는다.

## 규칙

1. 파일명은 `장비이름_raw.csv` 형식으로 통일한다 (예: `NanoDrop_raw.csv`, `qPCR_Ct_raw.csv`).
2. **한 번 커밋된 값은 절대 고쳐 쓰지 않는다.** 오타나 오측정을 발견하면 새 행을
   추가하고 `note` 컬럼에 정정 사유를 남긴다. 원래 행은 지우지 않는다.
3. 전처리는 반드시 `scripts/data_preprocessing.py`를 거쳐서 `data/processed/`에
   결과물을 남긴다. raw 파일을 손으로 고쳐서 만든 processed 파일은 재현이 불가능하다.
4. 실험 데이터는 총괄 앱(`데이터 입력` 탭)으로 입력하면 자동으로 이 형식에 맞춰
   `data/processed/samples_log.csv`에 쌓인다. 손으로 엑셀 편집하는 것보다 이 경로를
   우선 사용할 것.

## 이 규칙이 왜 있는가

9월 실측 전, 시뮬레이션 데이터로 파이프라인을 검증하던 중 같은 조건인데
MAE 값이 `10.5757`과 `10.7214`로 서로 다르게 나온 사건이 있었다.
원인은 두 가지였다:

- **numpy NaN 비교 함정**: `numpy.array_equal()`은 기본값이 `NaN != NaN`이라
  실제로는 동일한 데이터인데 다르다고 오판했다.
- **원본 스크립트 미보관**: 재현 시도가 "같은 코드를 다시 실행"이 아니라
  "설명만 보고 독립적으로 다시 짠 코드"였다. 컬럼 순서나 NaN 처리 같은
  미세한 차이가 값 차이로 이어졌다.

raw 데이터를 고정하고, 모든 분석 스크립트를 실행 즉시 커밋하는 것이
이 사고를 근본적으로 막는 방법이다 (`docs/git_workflow.md` 참고).
